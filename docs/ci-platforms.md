# CI platform coverage

Every executing workflow job uses our `l3-ubuntu-26.04` Runs fleet. Runner labels establish routing; the Runs inventory and job receipt establish whether the backing instance is our AWS Spot instance. There is no provider fallback or external reusable workflow with its own runner policy.

The aggregate `Check` requires successful native Linux builds, tests, race tests, vulnerability checks, lint and coverage, plus compilation for foreign targets. Both the stable Go release and the root module's declared toolchain are checked. Examples and tutorials use their own module/toolchain files and retain separate module tidiness, build, test and race checks. Module tests include the existing renderer, input, signals, command execution and TTY/non-TTY tests.

Each module/toolchain job compiles its four foreign targets sequentially on one runner. The full quality graph has 15 jobs. Darwin and Windows packages and test binaries are cross-compiled for amd64 and arm64 with CGO disabled. The explicit `/bin/true` test executor prevents running foreign test binaries. These jobs provide compilation evidence only: macOS terminal behavior, Windows console APIs and OS-specific lint execution are not tested. The prior macOS/Windows execution matrix cannot run on the current Linux Runs fleet; native runtime parity remains unverified. A green `Check` certifies the checks described here, not native macOS or Windows validation.

The vendored build, lint, configuration-sync and release workflows derive from [charmbracelet/meta at 2031836b979f4138001f6b31cee3fc2cf3dc9c28](https://github.com/charmbracelet/meta/tree/2031836b979f4138001f6b31cee3fc2cf3dc9c28), covered by `.github/LICENSE.charmbracelet-meta`. All jobs use the same fixed L3 runner. Configuration sync retains pinned meta data and PR creation, but never replaces this fork's local workflow with upstream runner routing. Release keeps the existing GoReleaser Pro, registry, signing and notification steps; its library configuration is vendored, with its footer pinned to the same meta commit. File includes follow the [GoReleaser configuration include format](https://www.goreleaser.com/customization/general/includes/). Release publication still requires the existing repository secrets and is not exercised by branch validation.
